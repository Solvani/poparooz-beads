## Defect fixed

### Visible keyboard focus indicator

- Evidence: `brand-300` (`#9BCBC0`) produced a 1.80:1 focus outline against white, and the file input's visible label did not receive that outline because the label was a sibling, not an ancestor matched by `:focus-within`.
- Root cause: insufficient outline token contrast plus a selector/DOM-order mismatch for visually hidden file inputs.
- Fix: use the existing `brand-600` outline (5.87:1), place the hidden input immediately before its visible label, and target the label with an adjacent-sibling focus selector.
- Regression test: CSS contract asserts `brand-600` focus styling; ImageUpload and ImagePreview tests assert the input-label adjacency needed by the selector.
- Affected modes/browsers: all modes; keyboard users in every browser.
- Browser retest: the hidden input was focused in controlled Chromium and the visible Choose label computed to a 3px `rgb(47, 111, 100)` outline with a 2px offset.
